# T9 路线图切片批次 1（真正动手实现）

你现在不只是验证者，也是实现者：用 Grok Build 在 Linux 上把路线图里的切片做出来，并用真实的 Linux 编译和 JVM 测试验证。Root 审后才合并，所以放心大胆做，但不要碰受保护文件、不要放宽任何测试。

## 资料（都在本分支）
- docs/slice-authoring-playbook.md：怎么做一个切片的逐条手册（归档目录与 manifest、需要同步登记的位置、生成器写法、测试写法、常见坑）。先完整读一遍。
- docs/roadmap.md 和 docs/roadmap.json：路线图。每个切片的详细条目在 roadmap.json 的 slices[]（按 id 查：upstreamFiles、firstStep、risks、coversEntries）和 entries[]。
- docs/root-decisions-roadmap.md：Root 对路线图里 12 个待决事项的决定（例如不要换 0.3.7 的小号字体基线、不要加大图片缓存、不要新增 Gradle 依赖）。
- 上游原文：本仓库 git 对象里有 d6bf8b1655ae910999860bf13e65c8fcea5b345b（v0.4.6）。git show d6bf8b1655ae910999860bf13e65c8fcea5b345b:<路径> 即可取到。不需要联网，也绝不能联系上游作者仓库。

## 基础分支与分支规则
- 基础：origin/desktop/integration-263 @ 89a0aee85（已推送；包含验收基线、评论修复线、NVIDIA 线、Veyra 重新钉扎、测试更新，以及 Root 的符号闭包检查 desktop/tools/check_slice_symbol_closure.py）。
- 所有切片按顺序累积在一个分支 grokbot/slices-batch1 上（每个切片一个或几个提交，提交信息写“Roadmap <切片 id>: …”，不加 AI 署名行）。每做完一个切片就快进推送一次，并在 grokbot-reports/slice-<id>.md 写报告。
- 不要为每个切片各开分支（它们都要改同样的登记文件，顺序累积才不会冲突）。

## 每个切片的验收
- compileKotlin、compileJava、compileTestKotlin、compileTestJava 0 错误。
- 该切片新增的 Python 测试通过；playbook 第 f 节列出的“改了生成器/归档/登记之后要跑的 Python 集合”全部通过（test_sync_upstream.py、test_validate_source_cohort.py、test_package_source_qualification.py 等；需要路径垫片的按垫片跑）。
- 受影响功能的 JVM 测试类（--tests）通过；不要把无关失败算到自己头上，但要在报告里列出与基线相比新增的失败。
- 如果 desktop/tools/check_slice_symbol_closure.py 存在（Root 的符号闭包检查，基础分支里应该有），也跑它，报告结果。
- 报告写清楚：改了哪些文件、关键设计、实际命令和结果、没验证的部分；区分“Linux 编译通过 / Python 通过 / JVM 通过 / 未验证”。

## 越界即停
需要改受保护文件、需要新增 Gradle 依赖、需要放宽测试、或发现路线图条目与上游原文明显矛盾：停，写进 STATUS.md 的 BLOCKED 和报告，然后做下一个切片。
