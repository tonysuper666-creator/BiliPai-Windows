对象：desktop/integration-263 的最新头。这三个测试在验收基线上就失败，都不在 Windows 验证计划里：
- test_extract_upstream_up_danmaku.py（2 项失败/10）
- test_extract_upstream_brand_success_mount.py（2 项失败/3；不带垫片时是 3 个路径错误）

沿用 T10 的方法，对每个测试：
1. 失败原文（带垫片）。
2. 根因：测试陈旧（生成器多了后加阶段、测试直接从最终输出撤销）、生成器逆向证明本身失效、还是测试夹具/路径问题？用 git bisect run（隔离 worktree，只读）找出第一个坏提交。
3. 是否影响实际被 Gradle 消费的生成器输出（对比修改前后生成的文件）。
4. 最小修复补丁（只改测试，除非证明确实失效）：写成补丁文件，推 grokbot/t11-old-python-failures（只含报告和补丁）。不放宽、不删除任何原断言，只允许新增校验。
