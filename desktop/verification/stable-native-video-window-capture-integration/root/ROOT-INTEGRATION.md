# Installed Window capture foundation

Candidate actual79 installs frozen Window33 byte-for-byte: the sole popup and
Windows WindowPort receive the native foreground availability contract; the one
Root capture owner requests Windows display affinity for the actual Root and
explicitly registered descendant foreground HWND. No registry/dependency changes.
Do not repeat Window33's 16 hunks during the full Root joint installation.

The concrete Root must construct exactly one DesktopWindowsVideoCaptureOwner
with its actual AWT Root window and lifetime predicate, pass it to the original
WindowPort, and forward only the sole popup's actual Window availability callback.
Fullscreen transitions, including direct F11/ESC paths, must consult its
orientationLocked. Close entry Window resources before the Root capture owner,
and close that owner before disposing the actual Root window. Native/EDT work
must remain outside Store, entry and native invocation gates.

Actual79 complete classes and static JVM-name audit pass. The zero-override
fixture verifies the two installed product class origins using the same frozen
101-entry classpath. It creates only three hidden owned test peers and reads back
real Windows display affinity through user32: root exclusion, owned foreground
inclusion, stale/double release, predicate retirement, foreground removal and
restoration, rejection of an unrelated fixture window, current-request retention,
owner close and late events. Its 30 assertions pass without availability errors.

This is real HWND/API acceptance of the capture owner only. Full WindowPort,
Main/Root mount, user-visible popup and PiP, physical capture pixels, original
player interaction and a packaged EXE remain unaccepted here. It is not a DRM or
photographic capture guarantee. No OS input or other application's window is used.
