# Focused actual full Offline native fixture

Compile only OfflineNativeFixture.kt against Root's immutable product snapshot, exactly 97 runtime entries and zero production overrides. Do not run until Root delivers the snapshot's manifest and ordered CP hashes. No shared Gradle, source changes, replacement platform classes or prospective helper JARs.

The fixture creates one temporary task/Store/window cohort and uses the previously frozen synthetic local clip. It directly calls the actual DesktopOriginalOfflineRootHost leaf adapter. That adapter supplies the full original Offline host, surface/window/media boundaries and PiP exclusion; no substitute implementation of those interfaces is produced here. Complete original controls, retained MPV, existing shaped popup, PiP actor, WindowsMediaSession, canonical preferences and actual chrome/client policy all come from the fixed product JAR. It reads only its own Skia backing, closes owned screenshot copies, and never invokes Robot or captures a screen rectangle.

Original controls are located through their actual semantics. Historical runs 08/09 show that PostMessage enqueue and AWT delivery do not establish the native key/cursor state needed by a real control: the observed press has modifiersEx=0 and coordinates differ from the original layout. Those runs are failures, not button acceptance. Current external-input mode does not synthesize mouse input. Root uses the computer-use skill's sky API to observe only the unique fixture window, click one visible original control and refresh. The fixture supplies a bounded per-step request/acknowledgement, validates its owned target window/native shape, and observes the resulting AWT press/release and actual original callback/state. It never invokes a semantics action shortcut, Robot, self-created SendInput, or PowerShell UIAutomation.

PiP uses the same actual MPV Canvas. The actual leaf adapter consumes its real active flow and suppresses the main Canvas/popup while the PiP window owns it. The adapter's actual floating/return buttons are exercised through native HWND messages, and restoration must return the same source token and original foreground. The fixture supplies actual standalone Window placement/current Chrome callbacks; it does not claim MainShell navigation acceptance.

SMTC uses true GetForWindow/native COM initialization, metadata publication and status readback. Seek/queue actions are injected into the existing actor's constructor callbacks on this fixture's EDT. They are explicitly fixture callback delivery, not OS media-button or hardware mouse acceptance. Missing queue targets cannot fall through into ordinary playback, and retired epoch callbacks must reject writes.

Real account login, the user's desktop/monitor input devices, MainShell navigation and OS media-button delivery remain outside this cohort. Each run is immutable; preserve failed runs, and repair only this fixture in a new numbered run if necessary.

The current normal fixture uses the product's application/Window/rememberWindowState lifecycle and mounts the full actual RootHost as its first media UI. It does not mount the historical blank→SwingPanel→empty-foreground diagnosis, load a temporary source, or enable JDWP. The Window starts inside its actual monitor with a positive origin; Root must not drag it to negative coordinates. If the visible layout needs adjustment, Root must inspect fresh sky output and preserve the measured geometry rather than guessing screenshot scaling.

Every input step records the actual Main/anchor/video Canvas/foreground window and Skia Canvas bounds, native GetWindowRect/GetClientRect, graphics configuration bounds and default transform, before and after input. Subsequent task/PiP/disposal observations retain the same raw geometry. These values support inspection; they do not by themselves claim correct layout. Native reattachment acceptance requires the actual ready state, configured video output viewport and exact source token, so a retained first-frame boolean cannot stand in for a new surface's native output.

Window placement/state, device full-screen support/owned identity, own-process focus/show/resize events and the original requested-effect sequence are recorded. An unsupported or rolled-back full-screen transition is retained as a failure and prevents full requested-scope PASS. Programmatic disposal placement and external F11 synchronization are independently reported; restored chrome alone is not proof of placement restoration. Historical closed01–13 and diagnostic14 receipts are immutable and independent of the upcoming normal product cohort.
