# Complete original message pages installed into the retained Windows Root

Inbox, MessageCenter, ReplyMe, AtMe, LikeMe, SystemNotice and Chat use their complete original v0.2.3 screen bodies, original Inbox/Chat/feed ViewModels and original message protocol. The existing Windows Community transport and epoch-tagged Repository admit requests. POST bodies retain original parameters, types and lengths with one-shot ownership to prevent implicit HTTP 503 replay. No additional client, pool, session, credential store or renderer is created.

Six actual typed message keys open physical retained NavDisplay entries; Inbox contains the original message-center layout. Per-entry and pane Chat scopes capture the existing Root gate, account epoch, caller Job and final state checks. Removed entries cancel and join their own work; the existing shared handle drains message work on restore, Store freeze and shutdown. Search, Bangumi browsing, the complete video content callback and its existing gallery share provider remain intact. The previous Community message surrogate is no longer selected.

Root applied five exact existing-file transformations, copied four canonical new files and preserved the source registry through thirteen append and four feature-union operations. The single message producer emits thirteen files; four pure policies are copied only by the existing upstream producer. The original adaptive Android dependency is 1.3.0; its explicit JetBrains JVM counterparts are adaptive and adaptive-layout 1.3.0-rc01, with official dependency identities retained in the frozen preparation.

Normal whole-product main and test compilation plus the actual JUnit runner executed all fourteen meaningful message tests with no product override. Cases cover original category cursor retry, stale refresh/more, notification cursors and delete parameters, Chat ordering/emotes/ACK, DND/top/interception, optimistic failure recovery, exact send/withdraw bytes, non-replayed HTTP 503 mutations, image-size/upload metadata, same-MID new epoch, caller cancellation and covered-entry admission. These use task-owned loopback responses and synthetic account state; they do not submit actions to a real account.

The real retained Root window, full wide MessageCenter/Chat UI, native image chooser, actual account responses and packaged EXE still need acceptance. Compilation and loopback tests do not establish full feature parity or fix real HTTP 412 responses. Both original frozen manifests, all non-binary preparation and failure evidence, exact Root installation backups, normal build log, JUnit XML and fresh native producer graph are preserved. Declared compiler intermediates and JAR/native binaries are byte-verified in the task-owned evidence and excluded from source control. The user's deployed EXE and account directories are unchanged.
