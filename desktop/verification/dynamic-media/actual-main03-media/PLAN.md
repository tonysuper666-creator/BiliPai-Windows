# Actual compiled Main integration only

This lane uses Root's new immutable actual Main snapshot03. It compiles only
four unique task fixtures. No product source, class, callback owner implementation,
writer, parser, decoder, Ops or Session is compiled into the fixture JAR. Any
production class overlap with the actual runtime graph fails the compile audit.

Fixture provenance is byte-pinned in fixture-adaptation.json:

- Frozen Assets114 download run05: retains the 51 assertions / 11 behavioral
  cases. Adds actual Main codeSource checks for Assets, Files, Exif and packing.
  The only network is a real task-owned exact 127.0.0.1 server; the declared
  fixture.invalid routing and dummy Cookie injection remain transport seams.
- Frozen cancel34: reuses its one final Store-lock wait cancellation concern.
  All prior candidate/Assets JAR paths are removed. Actual new Main Assets'
  private Files binding is reflected only to schedule the real final commit.
  Account/Assets stay alive, only the save Job is canceled, and the real Store
  monitor/blocked production stack is recorded. No HTTP or chooser for this case.
- Frozen Gallery233: retains original single/multiple result/read/close behavior
  and replaces the old synthetic epoch with actual Store same-MID rotation.
  Actual Main original result policy, GallerySelection and sole selected-image
  handle owner are required. Selection results are explicit task Paths; the
  real JFileChooser and the full editor UI are not run.
- Frozen QR88: runs its original eight declared synthetic long-ID routes once
  with all classes from new Main. There are no Canvas or renderer overrides.
  Actual original spec/QR matrix, Paint, PNG writer and saved images are checked.

The runner waits for accepted-snapshot-input.json written only after Root provides
the exact path, manifest hash, ordered runtime CP hash and entry count. It uses
that exact graph and never appends an older prepared classpath. The approved
Imaging/IO/Lang3 bytes are checked against the immutable official Gallery inventory.
Four fresh JVMs use short task-private runtime homes and all graph hashes are
verified before/after. Only fixture sources are compiled, without shared Gradle.

Independent Pillow/XML/MP4 readers check both account and MID0 guest downloaded
MotionPhoto outputs. This is compiled product integration proof, not execution of
the Root Shell, an actual chooser, HWND decoder, Photos recognition, packaged
runtime, system SHARE or receiver. No real Cookie/account material is used. Old
frozen cohorts remain historical evidence and are not relabeled as new Main runs.
