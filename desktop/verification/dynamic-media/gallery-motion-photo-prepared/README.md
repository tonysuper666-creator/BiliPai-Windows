# Gallery and Motion Photo prepared parity

This lane prepares the original alpha.9 gallery result policy, Motion Photo
JPEG/XMP/MP4 assembly, Windows JPEG codec, real EXIF writer and a narrow selection
adapter. It does not modify or install Main, Gradle or the source registry.

The immutable execution baseline is navigation Main manifest `4780b40c…0887c5`
with its actual ordered 89 CP `c2f31a97…b6ab`. The EXIF lane adds exactly three
approved Apache JARs for an explicit 92 CP. Every runtime JAR is byte pinned;
candidate/fixture JARs have zero class overlap with Main or dependencies.

Independent Python/Pillow readers verify all four tags, other EXIF including
UserComment, exact JPEG SOS/entropy/EOI and unchanged decoded pixels. XML readers
verify the XMP and actual MP4 length. FFprobe decodes the independently extracted
self-made MP4 tail. The JPEG source and FFmpeg testsrc MP4 contain no account or
user media. Tail extraction is an output verifier, not a new import feature.

The original XMP repeats three expanded attributes under `Camera` and `GCamera`
prefixes bound to the same namespace. The preserved `runs/02` XML failure is an
original format defect. Root approved deleting only three duplicate `GCamera`
modern attribute lines. Camera modern fields, GCamera MicroVideo legacy fields,
MiCamera, Container, segment parser/insertion and original MP4 append remain.
Before/after raw selected bytes and a unified diff are in
`generated-acceptance-final`. This follows [XML namespace attribute uniqueness](https://www.w3.org/TR/xml-names/#uniqAttrs)
and [Google's Motion Photo fields](https://developer.android.com/media/platform/motion-photo-format?hl=en).

The EXIF adapter maps Android Build manufacturer/model to the actual Windows BIOS
manufacturer/product using existing JNA core and [RegGetValueW](https://learn.microsoft.com/en-us/windows/win32/api/winreg/nf-winreg-reggetvaluew).
It writes the original Make/Model/DateTime/DateTimeOriginal tags with the original
formatter. It does not invent camera metadata. Fixed time and a separately
declared synthetic identity are fixture inputs only. The actual local Windows
identity path is also executed. Writer errors preserve the original raw-JPEG
fallback; cancellation and owner retirement propagate.

Apache Imaging `1.0.0-alpha6`, IO `2.19.0` and Lang3 `3.17.0` were downloaded only
inside this task directory. Official archive advertised SHA512 and Maven/archive
JAR byte equality were verified. Exact POM graph and LICENSE/NOTICE are retained.
The API mapping follows the [official Imaging example](https://github.com/apache/commons-imaging/blob/rel/commons-imaging-1.0.0-alpha6/src/test/java/org/apache/commons/imaging/examples/WriteExifMetadataExample.java).
Root must add the actual runtime graph and packaging after review.
