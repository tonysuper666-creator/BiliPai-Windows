# 动态时间线与崩溃提示证据

当前产品基于 de19778；主程序已接原两项动态设置、原时间线请求/分页/合并/页面策略和单一 Root 崩溃提示。源码来源与完成率分开记录。桌面仍为 0.2.406.5，未部署新包。

| cohort | 范围 |
| --- | --- |
| dynamic-producer-historical | 历史隔离准备；仅两个已声明旧消费者覆盖。其 13 JUnit、双风格 UI 与 transport 不冒充当前主构建证据。 |
| crash-producer-historical | 历史独立准备与初次 fixture 编译失败；保留原冻结身份。 |
| dynamic-main | 当前 c013 快照实际三 jar 优先，零生产类覆盖；8 UI 流程/48 pointer/40 PNG，实际 Repository、Community 和原 Retrofit 请求参数用 application interceptor 验证，无网络 socket。 |
| crash-main | 同一 c013 快照，零生产类覆盖；18 fresh JVM/278 fixture 断言；实际 Root 存储错误分支上的原提示、共享 actor 的 Viewer 与退休屏障。 |
| dynamic-fixture-compile-failed | 错误测试枚举包名导致的首个 fixture 编译失败，主产品编译成功；该失败没有执行 UI/transport。 |
| root | 主线 13 JUnit XML、7 Python 来源检查、446/210 来源审计、当前来源身份和清单纯顺序修正证明。 |

当前 Dynamic UI 证明覆盖 M3/Miuix、深浅色和 800/1200 宽：原开关/菜单真实 Press/Release 落盘后改变真实布局，布局切换不重请求；原增量 baseline、旧列表/分界与禁用后替换均验证。此处保留当前 Windows 卡片，不表示原完整 DynamicCard/栏目/UP 列表已经完成。

crash-main 的 278 个断言分为原 Host/磁盘 98、生命周期/Runtime 70、实际 Root 提示 110。Root 的 Ready 分支由损坏的隔离发现文件阻止，所以该证据不覆盖完整 Ready 主窗口或账号导航。原 SHARE/DISMISS 清标记且保留快照；原 IGNORE 只通过纯策略，界面没有额外按钮。Windows SHARE 当前进入同 actor 的本地 Viewer，原生外部分享仍待实现；Root 实际 OS 保存按钮没有点击，独立 Host 的文件选择 port 明确为 fixture。

所有成功证明固定 c013 快照的三产品 jar 和 231 有序外部依赖条目（226 个不同 jar）。快照完成后只恢复 upstream-sources.json 中旧条目的既有顺序并追加 13 个新身份，所有来源对象/字段/注册相同，编译 Kotlin/Java/资源及生成源码未改。before/after 原始清单与 canonical SHA 都在 root，当前提交的产品文件摘要另记录于 integration JSON。

dynamic-main 的真实 JVM 已完成全部 8 UI 流程后，Python 驱动向 GBK stdout 打印 Unicode 时失败；原始 ui.log、完整结果和截图保留。只恢复执行尚未运行的 transport，没有重复或降低 UI 门槛。compile-run-proof.json 清楚记录该基础设施异常。

Root 逐字节核验六个 cohort 共 982 个冻结产物，选取 255 项原始证据。类/jar/native dump、临时账号/存储及日志正文不入仓库。Root 复核双风格/深浅/宽窄布局、原分界、原提示和 Viewer 七张 PNG，控件与 footer 可见。离屏 Compose、隔离盘与 application interceptor 不表示 HWND、真实服务、用户账号、系统 chooser、原生播放或新 EXE 验收。完整功能及发布门槛仍未通过。
