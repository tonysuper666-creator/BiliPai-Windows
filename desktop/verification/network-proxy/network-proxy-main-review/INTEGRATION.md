## Correctness and failure-path review

The normal Main path gives the original singleton one synchronous global initialization before any Repository client is created. SessionStore construction only restores disk data. Runtime/package effects, Shell refreshAccount and resumed download metadata can then see the stored custom proxy from their first request. The backwards-compatible default DesktopApp tail initializes before Runtime but cannot retroactively govern API calls a separate caller made before mounting the app. CLI smoke/updater/automatic-backup independent clients are not silently changed.

The original selector evaluates the live cached configuration for each new route: valid enabled custom HTTP proxy, otherwise existing system proxy list, otherwise NO_PROXY. It does not change the global ProxySelector, add SOCKS, proxy credentials or system configuration. Original host/port validation and sanitizer behavior, including its colon limitation, are preserved. Failed proxy selection/connect remains an actual network error; the hook counts failures without URI, socket-address or exception-message logging. An enabled unreachable custom proxy does not silently bypass its configured route.

Original NetworkProxyStore saves the three original keys to the same `network_proxy_prefs` namespace. The Desktop SharedPreferences adapter persists and publishes atomically; failed disk replacement or a frozen restore backing throws before the singleton's cached/live state changes. Binding catches ordinary failures into Root's real error callback and propagates cancellation. It serializes writes from the one mounted settings binding. It does not add a parallel cached toggle or second store. Independent concurrently mounted bindings are outside the one Root screen contract; the original process-global Store does not provide a multi-writer lock beyond each mounted binding.

After successful changed settings, shared connectionPool.evictAll retires idle old routes.
