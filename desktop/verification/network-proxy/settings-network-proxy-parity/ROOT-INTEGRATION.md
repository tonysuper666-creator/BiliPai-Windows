# Original application HTTP proxy: isolated, actual graph/store/UI proof

This draft retains original NetworkProxyStore, all pure NetworkProxyPolicy schema/host/port/selection/format/sanitizer functions, original ApiClient proxy-selector and playback-client function, and the actual two HTTP-proxy controls plus complete NetworkProxyEditDialog selected from DiagnosticsSection. It binds them to the existing Windows SharedPreferences facade and same application HTTP graph. It does not implement a parallel proxy schema or substitute Cast's LAN media proxy.

Main, Root/Shell, shared Gradle, accounts, global ProxySelector and HWND were not modified. All HTTP happened between task-owned loopback sockets, with no real credentials. HTTPS proof observed the actual CONNECT request to fixture.invalid:443 through the task proxy, then deliberately rejected that tunnel; this does not claim a real TLS handshake, remote proxy service, or logged-in Bilibili request. Original advanced playback/FSR/native evidence is untouched.

## Earliest initialization and one retained store

Current Main normal application branch constructs Repository before DesktopApp. Current sources contain no restoreSession() network call: SessionStore construction restores saved disk content only. Shell later calls refreshAccount from LaunchedEffect and constructs PluginRuntime earlier, which may start package/plugin jobs. Nevertheless proxy settings must load before the very first API/auth/plugin request, rather than waiting for a settings page to open.

`startup-seam.kt.txt` gives a small Root-owned Main -> DesktopApp contract; `startup-baselines.json` captures Main/Shell/Session/Runtime/archive bytes at review time. Main first retains the actual existing global DesktopPluginStore and initializes original NetworkProxyStore through its existing Context facade, then constructs Repository. Main passes that same store to a compatible optional DesktopApp tail `applicationPluginStore: DesktopPluginStore? = null`. Shell uses supplied store, or its existing global default for older callers, and initializes it before Runtime. Multiple trivial Context wrappers around this one retained store do not create competing persistence authorities. Root can use the same Runtime context for the UI. These startup snippets are deliberately not applied/compiled as competing Root files, because Root is currently integrating its settings Tree/restore barrier.

Original NetworkProxyStore initialization is process-global and idempotent. This is appropriate for a global app proxy, not per-account proxy state. Preserve Root's actual restore fence plus exit/restart contract. Do not attempt in-process re-init with a different store while original initialized remains true. Existing DesktopBackupArchive includes global plugin-settings.json, and Runtime freezes the same actual backing during restore. The fixture proves that a late old binding cannot publish new settings after that fence. No new store-reset algorithm or account context is introduced.

## Scope and connection reuse

The application selector preserves the original live configured-proxy -> system-proxy-list -> NO_PROXY choice, original nullable URI/error handling and original HTTP-only schema. A tail systemSelector getter is the sole selection injection, defaulting to JDK ProxySelector.getDefault; it enables safe isolated tests without touching the user's global selector. Original connectFailed logged URI/address/exception text, which could include request contents. This Windows thin hook discards all of that data and counts actual failures only; it is not an enhanced-log collector/export feature.

The actual warm socket probe confirmed that the pinned OkHttp 5.3.2 can reuse an idle direct connection after the original dynamic selector is configured: originalUnretiredWarmRoute remained origin. After successful settings persistence, the thin binding evicts idle shared connections so the next warm request asks the selector and actually reaches the new proxy. Disable likewise returns the next request to direct route. It does not cancel or force-re-route a request already in progress; those retain original semantics. Eviction also retires any idle sockets in derived clients sharing that pool, without stopping active media downloads. Strict immediate retirement of all concurrent existing requests is not claimed and would need a separately reviewed graph/cancellation policy.

Root API and Community, login candidate, validation and captcha clients inherit the selector from the shared builder. The actual fixture exercises Community, actual login candidate and captcha clients while proving candidate CookieJar remains separate and captcha NO_COOKIES remains so. Original media builder explicitly uses Proxy.NO_PROXY. `media-caller-integration.patch` changes only existing DownloadManager media client and DesktopPluginServices.playbackClient to repository.playbackHttpClient; pinned baselines are separate. API/danmaku metadata clients continue to use the application graph. Native Mpv options/source headers are unchanged. This cohort proves the actual derived direct media client over loopback; it does not perform a complete download/mux/native playback acceptance.

Independent updater, JS/public-network, Coil/image, independent lyric and other separately built clients are not silently modified by the Repository seam. Their source-specific scope needs separate verification if Root later expects them to inherit this setting. This is neither an OS/system proxy switch, SOCKS provider, authenticated proxy editor, nor a change to Cast LAN serving. The original schema contains only enabled/host/portText, with original namespace network_proxy_prefs and keys enabled/host/port. No proxy credential or account-cookie merging is invented. Original host/sanitizer limitations, including its colon-based input behavior, are preserved.
