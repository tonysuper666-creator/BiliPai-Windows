   Register its `generate(repo, output, standalone=False)` call once with the
   normal generator pipeline. It emits 32 selected outputs in production.
   `standalone=True` emits all 53 outputs for independent source compilation.
2. Merge `registry-delta.json`: 52 original identities, 21 DIRECT outputs and
   32 selected outputs. SettingsManager has two outputs from one identity.
   Union the feature with existing identities and preserve unrelated modes,
   hashes, features and registry rows. Every DIRECT identity here is either
   new or already DIRECT; the normal sync copies those 21 originals once.
   Do not install `standalone-generated` as another production source tree.
3. Apply only the three exact `local-hunks/context-remove.json` hunks to the
   existing settings context. The jointly compiled base already contains the
   parent's StringSet additions; keep them. Joint base LF SHA is
   `2015e89458d5260276b442b142115de302709f7d62ba04ba8142418c9819c7e1`,
   desired LF SHA is
   `e749b7d0535d44f2ae66103caf6246ecc738b182b5d696a921079134531240c9`.
   The baseline and candidate whole files are reference evidence only, never
   whole-file installers. Nullable JSON patches preserve original
   `MutablePreferences.remove`; a removed value cannot reappear from the
   snapshot during the same edit. Existing global Store/updateFromSnapshot
   remains the sole persistence/admission authority.
4. Reference the parent's sole complete Playback VM and required environment;
   do not copy its candidate JAR, class, state models or producers. The Holder

   `DesktopOriginalVideoComposerEnvironment(entryScope, owns, commit)` and
   close it when that same entry retires. A temporary page cover is not entry
   retirement. Existing Engagement, comment and AI owners remain unchanged.

## Required Root binding

Provide `LocalDesktopOriginalVideoHolderPlatform` around the complete original
Holder/renderer subtree. The exact typed constructor surface is in
`manual/com/bilipai/desktop/ui/DesktopOriginalVideoHolderPlatform.kt`; unbound
use throws. No default callback, synthetic Activity, fake Media3 class or second
player/cache/client is supplied.

* `section` and `BindPlayerState(...)` reference the same Section/NativeOwner
  MPV facade. Preserve BVID/CID, resume milliseconds, initial pause, transition
  completion and session-active arguments in its existing source admission.
  Capture each actual request Job at the load/quality entry, not a completed
  page-held request. Window leases and deferred exit must reject replacement
  subjects and transferred publication identities.
* `window.presentation` reads the real Main Window placement/presentation and
  applies explicit original orientation requests. Physical rotation is an
  optional capability: a missing physical sensor is explicit; monitor/client
  aspect is not an accelerometer reading. Insets and multiwindow capabilities
  come from the same actual Root Window. Android system bars, automatic PiP,
  edge-to-edge and physical display rotation remain Windows capability mappings,
  not claims of Android OS equivalence. PiP, awake, chrome, brightness and
  exit leases affect only their unchanged registration/source.
* `playlist`, `mini`, `danmaku`, `downloads`, `portraitPlaybackOwner`,
  `commentsPlatform`, `accounts` and `favoritePreferences` are views of the
  already retained Root actors, document, account store and global settings.
  No list, cursor or account authority is copied. Danmaku click registration
  returns a same-source lease and disposes only that lease.
* `settingsContext` and `homeSettings` use the same global PluginStore.
  Original send color/mode/font keys, quality-failure once/shown deletion,
  hint scale/alpha and portrait recommendation defaults are selected verbatim.
  Existing Section/Control/Content/Reply/Tablet/Comment setting families are
  referenced instead of duplicated. Diagnostic logging still requires a real
  owned `setPlayerDiagnosticLoggingEnabled(enabled)` consumer: original
  SettingsManager lines 7427–7432 write `player_diagnostic_logging_enabled`
  then synchronize the player settings cache. Root must update the same key
  and same native diagnostic readback/cache; an empty implementation is invalid.
* `getStoryFeed`, feedback, screen/PiP analytics and log export/share must bind
  their existing owned transport/Root actors. The VIP account switch calls the
  actual Accounts port, awaits owned success, then retries on the same entry.
  No original API body is replaced by a flattened feed or fabricated status.
* `VideoCardMorphProgressReporter` is only the original reporter/local from
  VideoCardTransitionClock; provide it from the existing Root clock. This
  packet never creates another transition clock/timeline.

Store → entry admission is synchronous and only surrounds writes/registration
enqueue. Native close, actor barriers, waits, joins, disk/network work and
Window teardown remain outside Store/entry locks. Composer buffered events
cannot reach a retired collector; an already accepted in-flight event cannot
be unsent. Scheduler cancellation clears only its own delayed Runnable Job.
