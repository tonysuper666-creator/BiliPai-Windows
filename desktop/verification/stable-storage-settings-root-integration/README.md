# Original storage settings integrated with existing Windows owners

The original DataStorageSection, interval/threshold policy, six cache categories, default selection, confirmation and clear animation now use the existing Windows settings and cache owners. The existing folder chooser updates the canonical download directory and its synchronous download mirror through one DesktopPluginStore atomic replacement; the same DownloadManager captures that destination for new work. Queued tasks retain their captured directory. Existing SettingsShare, WebDAV and image-save destinations remain available.

Statistics and clearing use the same Coil ImageLoader, repository playback caches, media-byte index, subtitle assets, VOD danmaku owner, diagnostic writer and gallery share pool. Active readers, registered media, busy subtitle imports and live mode refuse unsupported clearing. Unknown or corrupt unowned files, user-imported subtitles, account state, history, favourites and downloaded payloads are retained. Temporary gallery clearing drains the same native actor before the one existing pool clears its owned files. Startup clearing excludes protected recipient files.

The existing Mpv worker continues its event loop after Stop until native idle acknowledgment. A maintenance token denies loads, recovery, subtitle installation and new native sessions throughout file IO. Detached sessions require actual termination acknowledgment; a timeout is never taken as unloaded. Settings restore and exit retire and drain the transient maintenance orchestrator before closing the existing owners.

Root applied 66 exact hunks in 19 existing families, copied only three new manual sources and one new producer, then added checked feature unions and three original source identities / one XML identity. The current standalone comment owner and typed settings routing are preserved. No new dependency, network client, preference authority, native player or sharing pool was added. The five normal producer outputs exactly match their prepared bytes. CacheClearUiPolicy remains direct and is produced solely by the existing prepareUpstreamSources task.

Normal standalone `gradle -p desktop classes compileTestKotlin` passed without product overrides. This compiles main and test code; it does not execute JUnit. Preparation separately passed 46 Store/cache/lifecycle assertions and the corrected native fixture passed 20 assertions using a real hidden Canvas, local paused media and the reviewed DLLs. The corrected fixture uses an existing SRT and verifies the required rejection exception; it supersedes that one insufficient missing-file assertion in native/01. Historical preparation failures remain raw and are not current product failures. Native Stop-to-idle was observed at 21 ms in that fixture, which is not a timing guarantee.

The actual Root settings window, ordinary Bilibili account playback, Windows Share receiver UI, long paths, the adversarial detach-timeout case and live emoji-cache clearing remain unaccepted. The desktop EXE has not been repackaged. Full original message/Bangumi/search and other remaining feature groups, v0.2.4 and the enabled public automatic update pipeline are still work to do.
