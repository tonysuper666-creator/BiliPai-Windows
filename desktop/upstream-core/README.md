# upstream-core: how the desktop compiles upstream sources

`core-data`, `network-core`, `design-tokens`, `design-system` and `plugin-sdk` are compiled straight from the merged upstream tree
(`../<module>/src/main/java`) into the desktop module. Nothing of them is copied into this repository. A merge of a new
upstream tag changes them in place. Where the desktop must differ, the difference is built **at build time** from the
files below; upstream files are never edited.

| Mechanism | Where | What it is | When upstream changes the file |
|---|---|---|---|
| Stand-in classes | `compat/` (JVM only) and `compat-ui/` (Compose, Skia, Miuix) | Real desktop implementations of the Android classes upstream imports: `SystemClock`, `android.graphics.Color`, `RuntimeShader`/`RenderEffect` (Skia runtime effects), `LocalConfiguration` (live window size), `colorResource`, `awaitFrame`, and the M0 set. Pure utilities only; anything that touches credentials, playback, windows or scheduling is a patch, a replacement or a loud failure (`UnsupportedDesktopCapability`). | Compile error if an API disappears. |
| Resource table | generated by `generateUpstreamColorResources` | `res/values` and `res/values-night` colors become `R.color.*` ids plus the table `colorResource` reads; night values win under a dark app theme. Any other resource kind or qualifier fails the build. | Follows the XML automatically. |
| String table | generated by `generateUpstreamStringResources` (TON-1000) | The upstream app `res/values` (default, Simplified Chinese), `values-en` and `values-zh-rTW` `strings.xml` become `com.android.purebilibili.R.string` ids plus one table per locale on the classpath; text is processed as aapt2 does. `Context.getString`, `Resources` and `stringResource` follow the system language with Android's fallback. Another qualifier, resource kind or styled markup fails the build; an unknown id throws. | Follows the XML automatically. |
| Drawable table | generated by `generateUpstreamDrawableResources` (TON-1072) | `res/drawable*` and `res/mipmap*` of the app and the library modules it depends on (Android's merged table; `brand-motion` today) become `R.drawable` / `R.mipmap` ids in each module's own namespace plus the packaged files and an index. `painterResource`, `ImageVector.vectorResource` and `ImageBitmap.imageResource` (Int) pick the variant Android picks (-night under a dark theme, anydpi, the nearest density bucket); vectors keep their root `tint`/`autoMirrored`, adaptive icons draw both layers in the AOSP circle mask, `res/values-<dpi>` mipmap aliases resolve to their target, and coil `Int` models (`AsyncImage(model = R.mipmap.x)`) go through `DesktopUpstreamResourceFetcher`. Colour references are resolved at build time (`@color/`, `@android:color/`, `?attr/colorControlNormal`). Another qualifier, reference or drawable kind fails the build; splash-screen `layer-list`/`bitmap` drawables load loudly. | Follows the files automatically. |
| Rewrite rules | `desktopUpstreamRewriteRules` in `build.gradle.kts`, applied by `applyDesktopUpstreamPatches` (TON-1072) | One call that every upstream file needs adapted the same way: coil3 `ImageRequest.Builder(context)` and `SingletonImageLoader.get(context)` take a coil `PlatformContext`, upstream passes an Android `Context`; the rule turns them into the same-argument bridge calls of `com.bilipai.desktop.compat.coil` (the JVM's single `PlatformContext`). `Context.imageLoader` and `allowHardware` resolve through `compat-ui/coil3` without a rewrite. Applies to every root-compiled upstream file that contains the call, after its patch. | A new upstream file is rewritten automatically. |
| Credential protection | `patches/core-data/.../SessionStorageCipher.kt.patch` + `com.bilipai.desktop.data.DesktopCredentialProtection` (TON-1000) | Upstream session encryption seals through the desktop platform interface (Windows DPAPI; a labelled test-only implementation selected by the Gradle test task on other hosts; a loud failure anywhere else) and throws instead of returning null or "". Android Keystore itself stays guarded (`DesktopAndroidKeyStoreGuard`). | Same as patches. |
| Patches | `patches/<repository path>.patch` (e.g. `patches/design-system/src/main/java/com/...kt.patch`; one mechanism, `applyDesktopUpstreamPatches`, shared with the other desktop fixes of upstream files) | Counted unified diffs applied to the merged file (dialog window flags, font padding, clipboard, window identity, press glow, lens uniform cache, backdrop recording hook, ...). | A hunk that no longer matches fails the build; a person re-reads the change. |
| Replacements | `replacements/<upstream path>` | Desktop implementations of files that are entirely Android windows (`AppWindowBlurBehind`, `AppDialogWindowExitEffect`). The first line pins the SHA-256 of the upstream file; the replacement must declare every public top-level name upstream declares. | The build fails until the replacement is reviewed and the pin is updated. |
| Plugin platform (TON-1028) | `app/.../core/plugin` + `plugin-sdk`, patches under `patches/app/.../core/plugin/` | The upstream plugin manager, stores and feed code run over the desktop plugin platform: `asAndroidContext()` hands upstream an Android Context whose preferences, settings_prefs, assets and change listeners are the plugin store's; `PluginStore` keeps plugin_prefs in that store, subscription/article/install writes and feed requests keep the desktop subscription admission, and `PluginManager` uses the shutdown-tracked scope and the caller's ownership check. Android-only files (WebView JS runtime, WorkManager statistics worker, Coil image loader) are desktop-owned. | Same as patches. |
| App data layer (TON-1071) | `upstream-core/data/later-steps.tsv`, `upstream-core/data/retired-generated.tsv` | `app/.../data/repository` and `data/model` compile from the merged root like the M4b feature areas. A file listed in `later-steps.tsv` keeps its legacy copy (with what it waits for); `retired-generated.tsv` lists producer copies whose names upstream now owns; mixed producer copies drop the re-declared names through transition patches. | A new upstream file compiles automatically; a conflict fails the build. |
| Transition patches | `transition/patches/<producer>/<generated path>.patch` | Patches against the output of a not-yet-migrated producer (the legacy app copies). Deleted together with the producer. | Same as patches. |

Guards: `verifyUniqueClassNames` (one class name once in the runtime classpath), `verifyUpstreamReplacements`,
`verifyNoSilentSdkGates` (no `SDK_INT` gate may stay in a migrated design file unless it is listed with a reason, because
the `Build` stand-in reports a fixed level).

Generated legacy copies of a migrated module are skipped by identity (`com/android/purebilibili/...` path), so a producer
that still emits one is harmless; `upstreamOwnedGeneratedCopies` lists the renamed subsets upstream now owns.

Upstream's own design-system tests run in the desktop test set (`design-system/src/test`). Those that read upstream sources
by relative path run in `upstreamDesignSourceTests` with the module directory as working directory.
